공통 실행 인터페이스

Skill:
  name: 스킬 식별자
  description: Planner가 스킬을 고를 때 읽는 설명
  args: 대상 물체와 목표 위치
  instruction: VLA에 직접 주는 명령
  can_start: 시작 가능한 상태
  done_when: 성공 및 handoff 조건
  max_steps: 제한 시간

SkillResult:
  status: SUCCESS | FAILED | TIMEOUT
  predicates: 종료 시 simulator 상태

실행 규칙 — can_start일 때만 실행하고, done_when이 참이면 종료한다. 시간 안에 충족하지 못하면 실패 결과를 Planner에 돌려준다. 다음 스킬은 계약에 고정하지 않고 VLM Planner가 현재 상태를 보고 선택한다.

01

GRASP_OBJECT

adapter: grasp 
name: GRASP_OBJECT
description_template: "Grasp {object} at {grasp_region}."
args_schema:
  object: ObjectRef
  grasp_region: RegionRef
  min_lift: Distance
  stable_steps: int
  max_steps: int
instruction_template: "Grasp {object} securely at {grasp_region} and lift it clear."
can_start: reachable(object) AND NOT held(object)
done_when:
  held(object)
  AND lifted(object, min_lift)
  AND stable_for(stable_steps)
  AND no_disallowed_contact(object)
02

MOVE_OBJECT

adapter: move_holding 
name: MOVE_OBJECT
description_template: "Move {object} to {destination} while maintaining grasp."
args_schema:
  object: ObjectRef
  destination: TargetRegion
  position_tolerance: Tolerance
  stable_steps: int
  max_steps: int
instruction_template: "Move the held {object} to {destination} while maintaining a stable grasp and avoiding disallowed contact."
can_start: held(object)
done_when:
  held(object)
  AND at_target(object, destination, position_tolerance)
  AND stable_for(stable_steps)
  AND no_disallowed_contact(object)
03

PLACE_OBJECT

adapter: place 
name: PLACE_OBJECT
description_template: "Place {object} at {destination}, release, and retreat."
args_schema:
  object: ObjectRef
  destination: SupportRef
  pose_tolerance: Tolerance
  clear_distance: Distance
  max_steps: int
instruction_template: "Place {object} at {destination}, release it after it is stably supported, then move the gripper clear."
can_start: held(object) AND near_target(object, destination)
done_when:
  supported_by(object, destination)
  AND released(object)
  AND pose_valid(object, pose_tolerance)
  AND gripper_clear(object, clear_distance)

         min_lift: 0.05m, stable_steps: 20, max_steps: 208}
  instruction: "Grasp the blender lid securely at its handle and lift it clear."

MOVE_OBJECT:
  args: {object: blender_lid, destination: closed_preplace_region,
         position_tolerance: {xy: 0.06m, z: [0.015m, 0.25m]},
         stable_steps: 3, max_steps: 288}
  instruction: "Move the held blender lid to the pre-place region above the blender while maintaining a stable grasp and avoiding disallowed contact."

PLACE_OBJECT:
  args: {object: blender_lid, destination: blender,
         pose_tolerance: {upright_error: 7deg},
         clear_distance: 0.15m, max_steps: 96}
  instruction: "Place the blender lid on the blender, release it after it is stably supported, then move the gripper clear."
일반화 규칙 — skill 이름, description, instruction, 시작·종료 조건에는 특정 물체나 task를 넣지 않는다. held · lifted · at_target · supported_by · released · pose_valid · gripper_clear를 공통 predicate로 사용하고, 물체·목표·거리·각도·유지 step은 args로 전달한다. CloseBlenderLid 환경에서는 이 predicate를 기존 RoboCasa simulator 신호에 매핑한다.
왜 이 7개만 남겼나 — name · description · args는 Planner 선택에, instruction은 VLA 실행에, can_start · done_when은 안전한 시작과 종료에, max_steps는 무한 실행 방지에 필요하다. affordance, reward, recovery, verifier 주기, adapter 상세 설정은 학습·런타임 설정으로 분리한다.

3. 스킬 학습 및 검증

학습 계획
Training decision Zero-shot instruction probe → 필요한 skill만 SFT → RL 먼저 정의된 instruction으로 기존 정책을 평가한다. 충분히 제어되는 skill은 SFT를 생략하고, 구분되지 않는 skill만 기존 성공 trajectory로 grounding한다.

3.1 Zero-shot instruction rollout

학습 전에 정의된 instruction만 넣어 기존 정책의 skill 제어 능력을 측정한다.

  • GRASP는 reset, MOVE는 grasp 완료, PLACE는 pre-place 완료 상태에서 시작
  • 서로 다른 environment seed에서 초기 배치·형상·entry state를 무작위화
  • skill success · wrong-skill action · done_when 도달을 기록
  • 성공 뒤 추가 window에서 불필요한 행동 지속 여부 확인
  • 영상·predicate trace·action 차이를 저장

3.2 SFT 필요성 판정

Zero-shot 결과가 통과한 skill은 SFT를 생략하고, 실패한 skill만 grounding한다.

  • PASS: instruction별 행동 분리 + skill 성공 + manager가 done_when 감지
  • FAIL: 동일 행동 반복, wrong-skill 진행 또는 낮은 성공률
  • 실패 시 기존 성공 trajectory를 skill 구간으로 분할
  • 새 demonstration 없이 task goal + skill instruction을 부착
  • Xiaomi backbone 고정, 해당 skill LoRA만 짧게 SFT

3.3 RL 미세조정

Zero-shot 또는 SFT gate를 통과한 정책의 성공률과 강건성만 개선한다.

  • 주 알고리즘: skill별 Flow-GRPO (πRL Flow-SDE)
  • reward: simulator predicate 중심
  • GRASP: 안정 파지 · MOVE: 유지/충돌 회피 · PLACE: 안착/해제/후퇴
  • drop · collision · timeout에 penalty
  • 같은 entry state 안에서 group-relative advantage 계산, group 간 seed는 무작위화
  • LoRA adapter만 update하고 frozen base와 KL로 성능 붕괴 방지

3.4 검증 및 모델 선택

단일 skill 성능과 실제 연결 상태 성능을 함께 본다.

  • skill success와 wrong-skill execution
  • manager의 stop latency와 retry/replan 비율
  • drop · collision · timeout 비율
  • clean state 대비 chained state 성능 저하
  • 세 skill 연결 후 CloseBlenderLid 성공률

RL 시작 조건

같은 observation과 noise seed에서 instruction별 올바른 행동이 분리되고 각 skill이 done_when을 달성해야 한다. 통과한 skill은 SFT 없이 RL로, 실패한 skill은 grounding SFT 후 재평가한다. 실제 실행 중단은 외부 Manager가 done_when을 감지해 담당한다.

RL 환경 · 리워드 동기화 뷰어

영상을 재생하거나 슬라이더를 움직이면, 그 순간 로봇팔 상태(predicate)와 그 스킬의 학습 리워드가 함께 표시됩니다. 각 스킬은 자기 리워드만 0에서 시작해 계산하며, 스킬이 종료된 뒤 프레임(성공 후 표류 관찰 구간)은 리워드를 더 이상 누적하지 않습니다.

각 스킬이 학습 때 받는 리워드

핵심: 리워드는 모든 성공 조건이 동시에 충족되는 최종 시점에 한 번만 지급됩니다(use_milestones=False, settle_terminal 유지 — 중간 마일스톤 폐지). place는 그리퍼가 물러난 뒤 최종 안정 상태에서 판정하므로, 놓다가 흔들려도 마지막에 안착+수평이면 성공. hold shaping은 스킬이 성공한 뒤 "그 자리에 멈춰있기"를 학습시키는 항(정지 보상·이탈 감점) — SFT로 못 고친 "성공 후 표류"를 직접 교정하는 학습 전용 신호. 공통 감점: 파지 중 뚜껑 떨어뜨림 −0.25 · 운반 중 금지 충돌 −0.05 · 실패로 에피소드 종료(timeout) −0.10. 감점·shaping은 학습에서만, 평가는 순수 시뮬레이터 리워드(terminal+drop/collision).
